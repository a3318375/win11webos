# 部署交接 · 2026-10-23

部署方案已改为 Linux 物理安装，删除全部 Docker / Compose / Nginx 配置。Go 程序通过 CLOUD_STATIC_DIR 提供前端静态文件，与 /api 同端口，无需其他服务。

main 最后一个提交包含 [build] 时发布 GitHub Release：Linux amd64 / arm64 压缩包和校验和。工作流进行测试、编译与 amd64 安装 HTTP 冒烟验证。

install.sh 支持指定专用安装目录（默认 /opt/webos），完成后后台启动。bin、www、data、logs、tmp、cache、storage、run、config.sh 均在安装目录；不安装系统服务，不注册开机启动。升级前停止，配置和数据库保留。用户选择的下载目标及传输临时文件在该目标磁盘。当前日志每次启动保留上一份，单次运行持续追加。

本地 NAS 界面直接手填路径。deploy/dev-api.ps1 显式启用开发别名 /data → D:\tmp\res\data；正式安装不启用别名。后端仍保留允许目录校验和回环监听。

本机是 Windows，没有 Linux / Docker，安装脚本执行与 Linux 冒烟验证由工作流完成。使用方法见 README。

正式部署默认端口 9999，install.sh 第二个参数可指定端口，配置写在安装目录 config.sh；本地 Vite 开发仍为 5173。

硬盘选择第一版：/api/v1/local/disks 共享内存快照，5分钟 TTL/定时刷新，冷缓存同步采样，互斥合并请求并返回副本。只枚举 CLOUD_LOCAL_ROOTS 对应已挂载存储，通过 /proc 和 /sys 识别设备；直连 ATA 使用 hdparm -C（需系统安装和权限），运行时 suspended 禁用，无法安全识别的 USB/RAID/网络盘及 Windows 均 unknown 禁用。界面仅允许 active。尚未完成真实 Linux 硬盘休眠验证；缓存可能有5分钟滞后，现有文件访问/传输及后端路径校验仍会访问文件系统，此实现不是全应用禁止唤醒机制。

首次发布版本 0.0.1，Release 标签读取 package.json，使用 v0.0.1；后续发布需递增版本，提交信息包含 [build]。
